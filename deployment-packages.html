Deployment Packages

Ready-made toolkits for putting the standard into practice

A Deployment Package (DP) is a free, self-contained set of artefacts that helps a small company implement one part of ISO/IEC 29110: process steps, templates, checklists, a worked example and tool suggestions. You don't have to adopt the whole standard at once. Implement one package, see the benefit, then add the next. The 2025 guides list their supporting packages in an annex (Annex A of the Entry guide, Annex E of the Basic guide).

What's inside every package

All DPs follow the same 12-part structure, so once your team has used one, the rest feel familiar. The highlighted parts are the ones staff use day-to-day.

TIP

Section 3 maps the package to the exact ISO/IEC 29110 tasks it covers, and Section 10 to other standards such as ISO 9001, ISO/IEC/IEEE 12207 and CMMI. That's useful evidence when preparing for an audit.

  1. Technical description: purpose and why the topic matters
  2. Definitions
  3. Relationships with ISO/IEC 29110
  4. Overview of processes, activities, tasks, roles and products
  5. Step-by-step description of tasks, roles, products and artefacts
  6. Templates
  7. Worked example
  8. Checklists
  9. Tools
  10. References to other standards and models
  11. References
  12. Evaluation form (feedback to the authors)

Packages for the Software Engineering Basic profile

ENTRY PROFILE

Starter packages

Two draft packages, Project Management and Software Implementation, support the Entry profile for start-ups and projects of less than six person-months. A separate package describes a highly iterative process for the Entry profile. Annex A of ISO/IEC 29110-5-1-1:2025 describes the Entry-profile packages.

SYSTEMS ENGINEERING

For hardware + software

The INCOSE VSE working group has produced a set of packages for the Systems Engineering Basic profile, for companies whose products combine hardware and software.

TOOL GUIDES

Implementation guides

Short guides show how to run specific practices with common tools, for example version control and issue tracking. Modern equivalents such as Git and Jira or GitHub Issues work just as well.
